# Component registry (the registry is law)

doc 14 anti-duplication mechanic #1: **check this registry before creating any
component.** A near-duplicate (a second Badge, a third card variant) is a
rejected completion, not a style note. New components need a one-line "registry
has nothing that…" justification. The machine-readable mirror is
[`registry.ts`](./registry.ts); every entry must render on the
`/dev/kitchen-sink` route, in every state unless this file records otherwise
(see **Kitchen-sink coverage** below).

**All of that is enforced** *(2026-09-05, bead `ro-6bhm`)*. Until then the
registry worked only as long as every agent read a file voluntarily and updated
it honestly: nothing imported `registry.ts`, and no test checked either half of
its "keep it in sync" line.
[`scripts/component-registry.test.mjs`](../../../../scripts/component-registry.test.mjs)
now fails the build when a `.tsx` under `components/` has no entry, when an
entry names a file or an export that is gone, when an entry has no row in this
file, or when it has no demo in the gallery — and `KitchenSinkRoute` imports the
array to draw its contents list, so the index a reader sees is the registry
itself. Exceptions are exact and carry a reason each, in the coverage table
below and in the test beside it; an exception that stops being true is deleted
by the test's own pruning check. It is the sister of `ui-noun.test.mjs` and
`ui-lexicon.test.mjs`, which hold two other "true on the day it ran" rules the
same way.

## Tokens & rules (doc 14)


- **ListRow interaction is explicit:** `to` renders a navigation link ending in
  the › disclosure chevron (Apple's HIG mark for a row that drills in; it was an
  ↗, which reads as "leaves the product" and is also a row glyph for a move —
  bead `ro-ujb9.13`); optional `returnTo` preserves the originating screen.
  Evidence/actions render an expanding button with a ⌄ chevron. Static rows have
  neither affordance and no hover. Closed titles allow two lines, and zero is a
  visible value. A `Table` row that opens (`TableRow opens`) says the same on a
  phone: its stacked card draws the ›. The gallery shows all three interaction
  modes; these are desk patterns, not Wall replacements.
- **Severity owns attention color**: `error` / `warn` / `info` (slate) tokens,
  plus the **emerald** accent reserved for milestone-kind outcomes. The scoped
  non-attention systems are integration state (`connected` green / `error` red /
  neutral gray) and completed like-for-like chart performance
  (`trend-positive` / `trend-negative` at three intensity steps). Some tokens name
  **identity** rather than any kind of state: `search-bing` (a provider, always
  beside a text label) and the Wall's series identities (`traffic`,
  `financial-revenue`, `financial-cost`). The calendar feed pair and the
  split-flap's `live-up` / `live-down` left with the components that used them
  *(bead `ro-trai.20`)*. These systems retain glyph/shape encodings. A color
  literal in a component is a review-blocking smell — consume tokens from
  `src/index.css`.
- **State is scannable and never color-only** (doc 14): booleans and enums use
  a concise visible label with a registry glyph where useful. A chip is not
  mandatory for every state; compact text is often clearer. Missing/failing
  follows severity; operator-declined and not-applicable stay neutral/muted.
- **tabular-nums** is baked into `Kpi` (and every metric-bearing component);
  never applied ad hoc.
- **Compact trends are neutral** on the desk; D28's Wall draws its audience
  series in the `traffic` identity colour (bead `ro-trai.19`, doc 14 § Tokens),
  and every small chart's marks come from `ChartMarks`. The pre-D28 Wall's own
  `Spark` line and `DailyBars` count bars left with its cards (bead
  `ro-trai.20`); the desk's dated charts are `HeroChart`.
- **Performance color is comparative, never alarm color.** `DeltaChip` is
  neutral by default; a completed like-for-like comparison opts into the
  three-step green/red ramp. Arrows still carry direction.

  *(added 2026-07-31; a third strip 2026-08-04; the files renamed 2026-09-05)*.
  Three route-level sections under `routes/asset-detail/` state store facts the
  Tower cannot write: `WatchesStrip` in
  [`WatchComposer.tsx`](../routes/asset-detail/WatchComposer.tsx)
  (db/0012 — registration and evaluation live in the ingest worker),
  `ReclamationSection` in
  [`ActivityTab.tsx`](../routes/asset-detail/ActivityTab.tsx)
  (db/0015 Link outreach — status moves through
  `scripts/reclamation-import.mjs` and operator SQL, and a *won* link is a person
  confirming it on the page, never a rule), and `SiteHealthSection` in
  [`SourcesTab.tsx`](../routes/asset-detail/SourcesTab.tsx) (db/0014
  hygiene_checks, bead `ro-gct` — the nightly served-layer fetch runs in the
  ingest worker and the Tower cannot start one). All render `null` when their
  table has no rows for the asset, because a section with no data **and** no
  way to add any is a dead end rather than an invitation. None is a registry
  component: they are one-surface layouts over a payload slice, not reusable
  parts, and adding a component for each would put near-duplicates in the
  registry. Give a route section a registry entry only when a second surface
  needs it.
  **A watch names the task it is judging** *(2026-08-04, bead `ro-5e8.6`)*.
  `watch_windows.ref` resolves against the asset snapshot by bead id and
  renders the shared `HandoffBeadBadge`; an unresolved id stays visible as a
  typed monospace ref (`event`, `decision`, or `ref`) so a numeric annotation id
  cannot masquerade as another count. The badge replaces the ref rather than
  sitting beside it. A
  closed bead on an open watch still says shipped-not-proven in the badge hover
  and never borrows the evaluator's outcome language; only a closed watch may
  render `Improvement confirmed`, `Decline confirmed`, `No clear change`, or
  `Could not be measured`.
  **`SiteHealthSection` composes registry parts and adds no vocabulary**
  *(2026-08-04, bead `ro-gct`)*. The hygiene guard has written one row per
  (asset, check, day) since 2026-07-31 and nothing read it back, so the checks
  only ever reached a human when a rule fired — the wrong instrument for a family
  whose three founding cases are all slow declines (a home page serving 88 words
  for months, an AI crawler quietly disallowed, a sitemap shrinking week by
  week). A rule fires on a step change; only the history shows a slope. The
  section is `SectionCard` + `Stat` + `Spark` + `StateChip` + `AgeBadge`, with the four
  reading states mapped onto EXISTING tones: `ok` affirmative, `warn` caution,
  `error` critical, and `unreachable` **muted** — "the origin answered badly" is
  evidence about the asset and "we never reached the origin" is a gap in
  observation, so only the first is an accusation. A series shorter than three
  nights renders as a number with no line (doc 14), and a reading with no measured
  number is skipped rather than plotted as zero. Each tile ages the stored
  `observed_at` instant against the guard's 24-hour cadence; amber past 2× means
  the guard itself stopped. That badge replaces the old raw calendar date under
  the number, because freshness gets one visual representation per fact.

  compose it, not a component.
  **`/health` (the same page, renamed) became layered, and still adds no
  component** *(2026-08-09, bead `ro-034`)*. The 2026-08-08 home-uplink outage
  produced fifteen flags accusing six assets of being dark, so the register
  gained the row that was missing: the OS's own egress, derived from the

  layer with a `th scope="rowgroup"` heading — table structure rather than a
  styled row, so the grouping is something a screen reader can follow. Ordering
  is by blast radius: the OS's connection takes every lane down, one provider
  account takes its lane down everywhere, an asset's own wiring takes down one
  lane on one asset. Two things did **not** happen. No sixth state: an OS that
  cannot get out renders `degraded`, and the five-state chip vocabulary is closed.
  And `IntegrationSummaryStrip` gained no per-layer counts — three more chip rows
  would restate what the layer headings already show, and the one L0 fact that
  needs the operator arrives as the first entry in `UnblockerList` (whose action
  for that lane names the house uplink rather than a credential to configure).
  **`WatchesStrip` gained a way in, and kept its silence** *(2026-08-04, bead
  `ro-71r`)*. Registering a watch window was a hand-written POST carrying the
  operator bearer — the highest-friction action in the OS sitting on the one
  step that stops a verdict being chosen after the numbers arrive, so it got
  skipped. The Timeline section header now opens a `WatchComposer` beside
  "Record an event" (one composer at a time; two open forms on one section is
  two half-finished thoughts). Three things did **not** change. The strip itself
  still offers no control, because a registered comparison must survive learning
  the answer and the verdict belongs to the 03:30 job. It still renders nothing
  when empty — the action is in the header, so an empty list would spend three
  lines saying "none yet" on every asset that never opened one. And the
  composer is not a component: it is one surface's layout over
  `shared/watch-windows.ts`, whose derivations (baseline, offsets, predicate
  direction, refusals) are the reusable part. Its rule is **prefill, never
  relax**: every refusal it shows mirrors a 422 the ingest route issues anyway,
  and it offers no backdating control even though the route allows one, because
  a backdated window's final check can already have passed. A query seed adds
  two purpose-colored bands rather than more fine print: amber `UNCALIBRATED`
  (or blue `QUERY FLOOR`) states the query's retained archive evidence and
  threshold provenance; blue `QUERY-SCOPED` states the grain and no-fallback
  rule. The history is loaded on demand for that one query, never added to the
  asset payload and never borrowed from the site-wide series. Since
  `ro-5e8.9`, both site and query floors also read the full-horizon annotation
  calendar and discard any comparison crossing a recorded-change day. A
  complete calendar is blue `CHANGE-FILTERED FLOOR` (site) or `QUERY FLOOR`;
  an older/incomplete payload is amber `HISTORICAL ONLY` and explicitly says
  the floor is not change-filtered.
  **`WorkRoute` (`/work`, added 2026-08-01) follows the same rule and adds no
  component**: the whole board is `Card` + `WorkPanel` (the per-project counts,

  an epic whose bar meant something subtly different from the project's would be
  worse than no bar). Its epic cards, remainder group and parked lane are route

  **That board moved out of the route on 2026-09-04** *(bead `ro-l1ed.5`)*, to

  page's **Tasks** tab is the same component with `project` pinned to that

  The one registry change the bead made is a `to` prop on
  `WorkPanel` (below).
  Its remaining novel bit is deliberately *not* a component — priority renders
  as the query table's short lowercase token (`top` / `high` / `low` / `lowest`, and
  **nothing** for the default band, because a board where every row says
  "normal" hides the ones that are not). Like the two strips above it offers no
  control: writes to the task hub happen through `bd` in each repo, and the

  **`TaskRoute` (`/tasks/:id`, added 2026-09-04, bead `ro-l1ed.3`) adds no
  component either**: it is `PageHeader` + `Card` + `StateChip` + `Meter` (the
  parent epic's all-time child progress, the same use `/work` makes of it) +
  `EmptyState` + `OwnerChip` + `PropertyFavicon`, with `Button` and native
  inputs styled on the tokens for the editors — `KnobEditor`'s idiom (buffer a
  draft, one Save, an Undo in the toast) rather than `KnobEditor` itself, whose
  every write is a `ChangesetOp` against a config file and cannot express a `bd
  update`. Two novel bits, both deliberately local. Its **activity timeline** is
  not `Timeline`: that component renders `annotations` (deploy · model change ·
  incident · external) over a different table, and widening its `AnnotationKind`
  to mean "claimed" would make one component answer two questions — so the route
  redraws the same *grammar* (glyph node, connecting rule, label, relative age
  with the absolute on hover) and stays here until a second surface needs it. Its
  **Markdown renderer** is likewise a route-local parser: the Tower ships no
  Markdown dependency and did not add one, and the parser emits React elements
  rather than a string of HTML, so raw markup in a bead's description is text by
  construction and only `http(s)` / `mailto:` / site-relative hrefs become links
  at all. The one shared change it made is the point of the bead: `StateChip`
  gained an optional **`glyph`** that replaces its dot, so the task lifecycle
  (open circle · in-progress dot · blocked ban · parked snowflake · closed tick)
  reads on a chip in the SAME shapes `WorkPanel` draws on the cards and the Wall
  — an anonymous dot there would have said the tone twice and the state not at
  all. **The board and this page share one task face** *(2026-09-24, beads
  `ro-ujb9.200`, `ro-ujb9.202`)*: `routes/tasks/task-face.tsx` defines a
  task's status (glyph, tone, word, the unknown-status fallback) and its
  priority mark once, and the board's State cell, its row mark and this page's
  header chips all draw from it — a shared route module outside the registry
  because it composes only task facts, never a
  layout. **Other screens borrow it rather than restate it** *(2026-09-24,
  bead `ro-ujb9.240`)*: `askFace` is the one look of a row waiting on the
  operator (warn at every priority, a gate's `△`) on the board's inbox, Home's
  Waiting on you and a site's Needs you, and `UrgentCount` is the Sites table's
  "N urgent" in the top bands' ink. **A waiting task's verbs are defined once
  too** *(2026-09-24, bead `ro-ujb9.243`)*: `routes/tasks/ask-actions.tsx`
  gives the inbox row and this page's header the same Approve for a gate and
  Answer / Dismiss for an ask, through the inbox's Undo path, from the one
  rule `inboxAsk` (`lib/task-board-read.ts`); Claim and Close stay for
  everything else.
  **`/assets`' filter bar is route layout too, and its chips are `StateChip`'s
  own dot rather than a rival control** *(2026-09-04, bead `ro-pbzu.7`)*. The
  index needed four controls, and two of them — automation and attention — carry
  values that already own a glyph, so hiding their counts inside a `<select>`
  would have answered "how many are open?" only after a click, which is the
  opposite of doc 14's 2026-09-04 rule. They render as chips: `SeverityDot` for
  attention (the bucket showing the *worst* thing in it, so one error never
  advertises itself in warning amber), and the `STATE_TONE` dot for automation —
  the exported mapping, so the filter and the asset card's own footer chip can
  never disagree about what a color means. The glyph is `aria-hidden`, because
  the chip's words already name the state. Lifecycle status and the ordering
  stay native `<select>`s in the desk's existing input chrome, counts in the
  option labels: six values and no glyph do not justify twelve chips. It is
  **not** a second `Segmented` — `KnobEditor`'s stages a changeset op into the
  cart, this narrows a view and writes only the query string — and it earns a
  registry entry the day a second surface wants it.
  **The setup checklist is one new PRIMITIVE and one route section, not two**
  *(2026-09-04, bead `ro-28ma`)*. `ProgressRing` is a registry component because
  three surfaces draw it — the asset card in `/assets`, Home's status cell, and
  the asset page's Overview panel — and because no existing shape counts discrete
  steps at badge size (its row above carries the full justification against
  `Meter`, `SegmentBar`, `Stepper` and `Wizard`'s rail). The **panel** is route
  layout — `SetupChecklistPanel` in
  [`routes/asset-detail/SetupChecklist.tsx`](../routes/asset-detail/SetupChecklist.tsx) — following the `WatchesStrip` / `SiteHealthSection`
  rule: `SectionCard` + `ProgressRing` + a glyph list, over one shared derivation

  deliberately does not do. It does **not** draw on the Wall, even though

  counts the **nightly-report slot once**: that lane rides in the same fixed
  seven-slot inventory the data-sources item reads, so the derivation excludes it
  there, or a four-segment ring would move two segments on one event.

## Surface vocabulary (`components/surface/`, doc 21)

*Added 2026-09-05 (bead `ro-78qo.1`, decision D24).*
[Doc 21](../../../../docs/21-surface-design.md) is the contract every desk
surface is now built against, and this is the vocabulary it names. It exists
because the asset page's Growth tab measured **10,139px** at 1440 wide and its
Overview ran **2,600px** before its first chart: not because any one card was
wrong, but because the desk had three charts drawing the same shape, four ways
of drawing "a label and a number", three list panels and a paragraph under every
heading. The operator's brief — *"avoid overwhelming the user, while providing
the most impactful overviews in the most visually stunning way"*, with PostHog
and Ahrefs as the bar — is answered by having ONE of each.

Four rules hold across all eight. **Tokens only**, as everywhere here. **The
range is the page's one input**: the arithmetic lives in
[`shared/surface.ts`](../../shared/surface.ts) — windowing, the rolling average,
the delta against the prior period of the same length, provisional-point
detection, annotation placement — so a KPI's delta and the chart under it cannot
disagree, and `test/surface.test.ts` holds every edge without a DOM. **A phone
gets a layout, not a scrollbar**: strips stack to two columns below `sm`, the
hero chart stays full width, and every control clears the 44px floor through
`pillControlClass` (bead `ro-md80`). **Nothing decorative moves**, and the two
colour transitions that exist are behind `motion-safe:` / `motion-reduce:`.

**`DistortedDayMarks` is a chart primitive, not a component** *(2026-09-04,
bead `ro-kukv.8`)*. It lives in `Spark.tsx` beside `calendarWeekBands`,
`CountAxis` and `ChartRangeLabels`, and the supported Wall charts
`DailyBars` and `Spark` share it. The desk `HeroChart` uses its own plot geometry
and the shared `ChartEventMarkers` interaction for event-specific disclosure.
What it draws for a
day a reporting-timezone change distorted: a `chart-distorted-band` rect over
the day's own slot, a dashed `chart-distorted` bracket on each edge, and a pin
hanging from the plot's top edge — **rectangles and verticals only**, because
both charts stretch their viewBox on x and a triangle or diagonal glyph would
shear with the container width. The days are DERIVED from
`distortedByTimeZoneChange`, never from a date a component holds, and the one
sentence behind the mark comes from `distortedDayNote` in `shared/wall`, so the
hover on a bar, a point and a line all say the same thing.

**Which changes reach a chart is decided upstream, by provider** *(2026-09-04,
bead `ro-kukv.11`)*. A reporting timezone is a setting on ONE provider's
property, so `apps/tower/worker/signal-trends.ts` keys the changes it reads off
the annotation timeline by **asset AND integration** and hands each series only
its own provider's — GA4 series get GA4 moves, Search Console series get none of
them. It was the missing half of the mark: before it, every series of an asset
carried every change filed for it, and marking a GSC chart would have painted a
GA4 fact onto it. A knowingly wrong mark is worse than an unmarked day, which is
why `ro-kukv.8` marked only the active-users series and left the rest for this.

**Why it is not the provisional treatment** — the two are different claims, and
the kitchen sink shows them side by side. *Provisional* means the number is
still moving, so the mark itself is dimmed and the rolling line stops short.
*Distorted* means the day is finished and its number will never move again, but
the provider's day boundary moved and took hours from one day to its neighbour:
the value stays exactly as reported (operator decision, 2026-08-31) and the
furniture around it carries the caveat. Dimming it would say the opposite of the
truth. Its week-on-week color verdict IS withdrawn, on both sides — a clean day
measured against a distorted one is not a like-for-like comparison either.

**`TimeZoneCaveat` is the shared ⚠ for a straddled COMPARISON**, as

Making principle-10 knobs **two-way** needed two more. **KnobEditor** — KnobRow is
read-only; nothing composed a validated edit control with a Save, so this is a
distinct affordance, not a KnobRow variant (it reuses native inputs
styled with the tokens — no new form primitives). **StateChip** — doc 14's
state-scanning rule needed a compact boolean/enum state as a dot-glyph +
visible-label pill; nothing existed (SeverityDot is severity-only; Badge is
neutral chrome with no meaning-color), so this is the canonical state renderer for
enabled/paused, sense-only/full-loop, lifecycle, and sense mode. Two components
that lived here until 2026-09-04 are **gone**: `StagedBadge` (the inline
staged-edit marker) and `CartDrawer` (the header cart + slide-over), because
nothing is staged any more — a field saves where it stands and the way back is
the Undo in its toast (D18, bead `ro-pbzu.5`; docs/06 config-is-files;
docs/15 principle 5 "undo over confirm").

**Integrations UI (the register: doc 11 states + doc 15 principle 10 "integration
status").** Five additions. **StateChip** gained two token-based modifiers rather
than a rival — `dot=hollow` (the doc-11 "hollow notch" for skipped) and
`attention` (a soft same-tone halo for the unresolved needs-setup) — so the two
slate states read apart pre-attentively without a new color. **IntegrationStateChip**
maps the five lane states onto StateChip (it composes, never rivals it) so the
matrix, the asset section, the summary strip, and kitchen-sink render one glyph
per state. **EvidencePopover** — the "why this state" affordance for a lane with
store evidence (collector success/failure/staleness or a manual revenue lane);
portalled so the matrix's horizontal scroll never clips it. **IntegrationSummaryStrip**
— the count-by-state "does anything need me?" line; nothing summarized states before.
**IntegrationMatrix** — the portfolio grid (lanes × assets); reuses the Table
primitives + a sticky lane column, but the plain data-table block has no
expandable explainer rows or per-cell affordances, so the composed grid is its
own entry. There is deliberately no status editor: collector health is observed,
not declared.

**Alert language (insights, not evidence).** One addition. **ChangeChip** — the
correlated-change affordance on an alert line, used by both the Needs-attention
band and the asset page. It is deliberately not a `StateChip`: that renders a
*state* in a meaning color, and a nearby deploy is context, not a state —
coloring it would put a second severity signal on a line whose `SeverityDot`
already owns that (doc 14 one-representation). It shares `Timeline`'s kind
glyph + word (`annotation-kind.ts`), so a deploy is named identically in the
chip and in the timeline the chip links to. The alert *statistics* needed no new component:
`EvidencePopover` took them, with its panel copy now parameterized
(`question`/`blurb`) because the same glyph answers "why this state" for a lane
and "why this fired" for an alert.

**Alert lifecycle.** Two entries. **FlagActions** is shared by the desk
Needs-attention table and the asset alert row. Centralizing the actions
keeps their wording and pending behavior identical: “Mark read” closes this
event while a recurrence remains new; “Resolve” records that the underlying
issue cleared; “Snooze” hides it until a date the operator picks and then
returns the SAME condition. All reuse `Button`.

**Snooze needed a second entry, and only one** *(2026-09-04, bead `ro-c7qq`)*.
The verb itself is a variant of `FlagActions`, not a component — a queue with no
“not now” in it is what left four identical month-old rows untouched for four
weeks (`ro-kukv.6`), and the fix belongs under the row, in the control that is
already there. What the registry genuinely had nothing for is the *date*:
`StateChip` colors a state from a fixed vocabulary, `AgeBadge` ages a reading
against a cadence, `DeltaChip` compares two numbers — none of them says “this
comes back on the 7th, in 3 days.” Hence **SnoozeUntil**, which THREE
surfaces render and which therefore has to say it in one voice: `AlertRow`
draws it in its parked mode on a site's Snoozed panel (until bead `ro-ujb9.194`
it drew it in the History footer, which filed a live snooze as settled), and
the `/alerts` Snoozed list draws it beside its Unsnooze. In that footer it also REPLACES the disposition badge
rather than sitting beside it: “Snoozed” plus “quiet until Sep 7” is one fact
rendered twice, and the badge is the weaker half. The Snoozed list itself is
NOT `AlertRow` — that renders one alert whole over a `FlagRecord`, and a
ledger line over the wall payload's `AttentionItem` is a different job — but
both facts on it (the date, the way back) come from the shared components.

**Where “open” is decided.** Not in a component at all, but the rule that keeps
these two honest: a snooze is the only disposition that EXPIRES, so “open”
became time-dependent, and `apps/tower/worker/flag-scope.ts` is now the single
SQL definition every payload composes (the Wall's rail and aggregates, the
asset page's hero, counts, wiring flags and history, the integrations lane
read, and the write lane's own eligibility check). Six hand-written copies of
`resolved_at IS NULL AND disposition IS NULL` were correct only while every
disposition was permanent; the first one to learn about snooze without the
others would have had Home, `/alerts`, the hero and the TV counting different
portfolios.

**Tuning a rule** *(2026-09-04, bead `ro-u072`)*. Two additions, and the split
between them is the justification. **BacktestStrip** is a *shape for a quantity*
— it draws thirty days and would have been a near-duplicate of nothing in the
registry: `Spark` and `DailyBars` draw counts on a continuous scale, and this
draws a four-valued STATE per day against a second track of what really
happened, which neither can express without becoming a different component.
**TuneRuleAction / RuleTunePanel** is a *composition*: `Button`, a portal on
`EvidencePopover`'s contract, `BacktestStrip`, and three `KnobEditor`s. It adds
no new editing idiom, no second Save behaviour and no second answer to what
`alpha` is called — `KnobEditor` gained exactly one prop, `onDraft`, so a
preview can recompute before the Save instead of after it, which is the whole
of docs/15 principle 1.

**Pulse totals on the Wall.** `SiteRows` restores selectable asset totals
beneath each site's traffic row (2026-09-30, `ro-trai.46`). It reuses the
counter resolver and `AgeBadge`; `lib/wall-counters` shares default and saved
selection rules with the existing Wall editor. This adds no general card or
new Save flow. The Wall's live users remain `LiveUsers` over `MinutePulse`.

**The booking split added no NEW vocabulary — it added one chip, three times**
*(2026-08-02, beads `ro-qes` → `ro-uwo.2` → `ro-jk7`)*. Booked versus forecast
money is a *state*, and the registry already renders states, so `PortfolioBand`
started by composing two `StateChip`s — `affirmative` + solid dot for
Reconciled, `na` + hollow notch for Forecast. That is deliberately the same
solid/hollow pair the integration lanes use for "settled" versus "not settled",
so an operator who has learned the notch once has learned it everywhere, and it
keeps the split off the severity palette: estimated money is not a *warning*, it
is money in a different state. Two encodings (fill **and** tone) mean the
distinction survives a glance at a TV across the room. A "ForecastBadge" would
have been a second chip vocabulary for a fact the first one already says.

Those two chips became `BookingChip` the moment a second surface said the same
thing (asset cards, `ro-uwo.2`), and the third surface — the asset page's
P&L — was where the cost of *not* having done that showed up: it had quietly
grown its own `Badge` printing the lowercase word "reconciled"/"estimated"
beside the same money. `ro-jk7` deleted it. The rule this leaves behind is the
registry's own, stated in money: **a fact stated on two surfaces is a
component**, and the second surface is where you find out.

**The split runs all the way down, not just at the headline** *(2026-08-02, bead
`ro-jk7`)*. `PortfolioBand`, `AssetCard`, and the asset page's P&L tile all
state a booked figure with the estimates below a rule, and all three draw the
booked line *always* — an em dash when nothing has reconciled — so the loud
number in any of them is unambiguously the booked one and a lone forecast can
never slide up into its place. Which side renders is one shared derivation,
`figureHasMoney` in `shared/wall.ts`: three zeroes are not a figure, but a
reconciled `$0` somebody confirmed is a fact and shows.

**A band with no numbers does not mount** *(2026-08-02, bead `ro-yf3`)*.
`PortfolioBand` is entirely money — a booked headline, its trend, and the
forecast block. Before the first ledger row there is none of it, and what was
left was a title, an age badge with no date, and an empty-state sentence
explaining the card's own emptiness. Absence is the honest render, so the band
returns `null`. The rule is one exported derivation, `portfolioHasData` in
`shared/wall.ts`, next to the type it reads — not a payload flag (a held
last-good payload could then disagree with the Worker that built it) and not a
condition copied into each route (a new surface would forget it). The guard sits
in the component, and every mount is a plain flex child, so the column simply
closes up. The **first** row of either kind — reconciled or estimated — brings
the card back unchanged, and a reconciled row worth `$0` is data, not emptiness:
`firstRun` is already false, and a zero somebody confirmed is a fact.

**An empty current month is not an empty ledger** *(2026-09-04, bead
`ro-bdkp`)*. Every row here lands by import or by hand, so the first days of a
month hold none — and the guard above, reading only the current month, took the
Wall's money card away for those days on a surface D13 says must lead with
money. `wall-payload` now picks the latest period with rows (the current month
whenever it has one) and feeds the band **and** every property card from that
single choice, so `ro-uwo.2`'s add-up invariant survives the fallback. Because
the period moved, the card **names** it — `August 2026 · latest month on the
ledger`, full month and year, since every other month label on this card is
about the open month. `periodIsCurrent` on the payload is what says so; the two
places asserting an open month (the sparkline's provisional tail, the delta
chip's "still open" sentence) go quiet when it is false.
