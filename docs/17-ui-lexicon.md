# 17 — UI lexicon (the demoability contract)

*Added 2026-07-06. The Tower must be demoable to someone who has never read
docs 00–16: every label, section title, and description uses plain English or
a term with a popular industry precedent (Zinsser's bar: if a simpler word
does the job, the fancier one is wrong). The system vocabulary in docs 00–16
and the schema is unchanged — this doc maps it to what renders. Internal
coinages may survive in the UI only with a justification recorded here; an
unmapped internal term appearing in a UI string is review-blocking (doc 15
principle 9 enforces this doc).*

## Current navigation and setup language (2026-09-05)

| Concept | User-facing name |
|---|---|
| `/health`: observed collection health across assets | System health |
| `/integrations`: provider credentials and account connections | Integrations |
| `/assets/:id/sources`: per-asset connections and mappings | Data sources |
| Stored `assets.status`, edited by the operator | Manual lifecycle stage |
| An asset that has at least one Working source (the Sites page's count only) | receiving data |
| A connection's one status — provider, site, or one data source on one asset (`shared/connection-status.ts`, bead `ro-ujb9.96.7.3`) | Not connected · Not checked · an accepted connection named for what was given — **Key accepted** for an API key or token, **Signed in** for an email and password or a Google sign-in, **URL accepted** for an address that is itself the secret (a webhook, a calendar feed); one derivation, `acceptedAs` in the contract from the provider's declared `connect.credential`, bead `ro-ujb9.96.7.25` · Collecting · Working · Overdue · Failing · Not using · Unknown; its facts as chips: "N sites failing", "N reports missing", "N reports incomplete". The uptime source reads **Up** for Working and **Down** for Failing, because its check observes the site itself — "Failing" would read as the monitor being broken (`connectionLabel`, bead `ro-ujb9.165`) |
| One data source on one asset in the asset header, Home and the Wall (`DataSourceIcons`, bead `ro-ujb9.96.7.16`) | the same status word as its Data sources row, as the mark's name ("Bing Webmaster Tools API: Failing"); the header no longer carries a one-word verdict ("Receiving data", "Configured · not verified" are retired) |

Lifecycle never claims a connection is working. Report coverage counts actual
report dates, not elapsed time, and does not promise every alert rule is ready.
Technical keys and file paths belong behind **Technical details** on normal
forms; form labels and save confirmations use the plain-language name.
The Wall keeps its TV-specific presentation; its separate visual evolution is
tracked by `ro-ujb9.26`.

## Altitude (2026-10-08, D44)

A founder reviewer called the product "technical". The lexicon above maps
coinages to plain words, but plain words at the wrong altitude still read as
machinery: "4 / 6 fresh · 12 jobs" is English, and it is the OS talking about
itself on the first screen. So every word has an altitude, and a surface shows
its own altitude or lower, never higher
([brief](briefs/2026-10-08-home-overview-redesign.md#language)).

| Altitude | Surfaces | Nouns | Verbs and verdicts |
|---|---|---|---|
| **Business** — what a founder steers by | Home · a site's Overview · TV mode | money, revenue, costs, people, visitors, search, bets, decisions, wins, sites | on track, at risk, off track, ahead, usually N, verdict in N days, measured, unmeasured, still counting, approve, keep, revert, snooze, seen |
| **Operational** — how the work is run | Alerts · Tasks · Workflows · a site's Activity, Bets, Alerts and Tasks tabs | alert, watch window, holdout, change, verifier, run, schedule, snapshot, gate (as "needs your approval") | fired, resolved, win, revert, not yet significant, building, verifying, shipped, reverted |
| **Technical** — where the numbers come from | Data sources · System health · Integrations · Settings · a site's Sources and Settings tabs | GA4, Search Console, Bing, Mediavine, PostHog, DataForSEO, Clarity, job, nightly report, freshness, credential, property id, lane (never on screen) | collecting, working, overdue, failing, provisional, reconciled, estimated, stale, fresh |

The rule, mechanically: a word in a lower band may not appear on a surface in
a higher band. A business surface says "being watched · verdict in 3 days",
never "watch window"; "still counting", never "provisional"; "people a day",
never "GA4 users". A technical fact a business surface must carry is said in
business words. A provider's name may appear on a business surface only as a
chart key beside its own line (doc 14: Bing's blue is always beside the word
"Bing"); never as a label, an eyebrow or a caption.

**Enforced** by `scripts/ui-lexicon.test.mjs` (rule 9 below): the business
surfaces' files carry the lower bands' words as banned, with the chart-key
exemption as exact phrases. A word moves up a band only by a decision
recorded here.

Rows this adds to the map:

| System term | UI renders | Why |
|---|---|---|
| `/financials` in the navigation | **Money** | the founder's word; the route, the payload and the asset tab's id keep `financials` |
| `watch window` (business surfaces) | **being watched · verdict in N days** | the window is machinery; the verdict date is the fact |
| `ship_confirmed` / `kill_confirmed` / `inconclusive` / `unmeasurable` | **win** / **revert** / **not yet significant** / **unmeasured** | GrowthBook's and Eppo's words; never a number for unmeasured |
| `provisional` (business surfaces) | **still counting** | the same honesty, in the reader's word; the hollow point is unchanged |
| the Poisson baseline (`avg7d 39.3`) | **usually 39** | one baseline word everywhere, the alert headline included |
| `gate` (business surfaces) | the sentence of the ask, with **Approve** as its verb | the id and the mechanism never reach a view row |
| ingest freshness on Home | nothing, unless broken: **"One site stopped reporting"** as a highlight card | the fraction keeps its one phrasing on System health |

## Rules for new strings

1. **Check this doc first.** A term already mapped renders as its UI term —
   no re-derivation, no synonyms (one concept, one word, everywhere).
2. **New internal concepts get a mapping before they get a label.** If no
   industry precedent exists, write the plainest honest phrase and add the
   row here; a justification is required to keep an internal coinage.
3. **Parenthetical jargon** (doc 15 principle 9) is for *system* terms an
   operator will meet in configs or docs ("Automation (`sense_only`)") — not
   for decorating plain words, and subject to doc 14's one-representation
   rule.
4. **An alert says what happened, never what it measured.** Any line the
   operator is meant to act on has three parts and only three: **what
   happened** (plain words, magnitude included), **how sure** (the severity
   dot — never restated in prose, per doc 14), and **what now** (a next step,
   or a change that correlates with it). Statistics — baselines, tail
   probabilities, thresholds, raw counts — are *evidence*: they belong behind
   the evidence glyph, never in the headline. A line that reads as a
   measurement rather than an event fails review even when every word in it is
   plain English.
5. **A direction is never left to the reader.** A headline that states a
   movement states which way is *good*, in the verb: a metric where up is bad
   says improved/worsened (row above). "Up 10.14%" under an amber dot is three
   signals pointing two ways *(2026-09-04, bead `ro-kukv.3`)*.
6. **Missing says missing; a dash is not a number.** Where a figure is
   expected — a stat, a headline, a labelled value — an absent reading is
   NAMED ("OS report missing", "No comparable week yet") or the
   slot is not drawn at all, and no derived visual is drawn over the hole
   either (no meter at zero for a spend nobody reported). An em-dash there
   reads as a rendering failure, and the Wall was already honest about the
   same gap while the desk card was not. This is about *number slots*, not
   about a dense table cell, where a dash under its own column heading is the
   ordinary convention *(2026-09-04, bead `ro-kukv.3`)*.
   **A MEASURED zero is not a hole** *(amended 2026-09-05, bead `ro-sq42`)*:
   the words above are "a spend nobody reported", and the SYSTEM band's spend
   was exactly that until it stopped coming from asset #0's report and started
   being counted over the OS's own record of the metered calls it made. A day
   with no call now reads **$0.00** with its meter drawn, because the figure is
   known — and hiding the row would leave *nothing was spent* and *nothing is
   known* looking identical, which is the confusion this rule exists to end.
   Spend also left that warn line for the same reason: a band naming it as
   missing self-observation would be reporting a gap that was closed. The test
   for which side of this rule a figure falls on is not whether it is zero but
   whether anything measured it.
   **A reading nothing produces is not missing** *(amended 2026-09-23, bead
   `ro-trai.1`)*: "missing" is for a figure something owes. The SYSTEM band
   named agents and queue as missing whenever asset #0's report lacked them,
   but no part of the OS produces either, so the warning was permanent on
   every install. Such a slot is not drawn and turns no state.
   **A shared formatter's dash is not the surface's answer** *(amended
   2026-09-04, bead `ro-kukv.10`)*: where a helper is used by both a labelled
   slot and a dense cell, the helper keeps the dash and the COMPONENT THAT
   KNOWS THE FACT names the absence. `formatAge` still returns `—` for an
   unknown age, because fifteen call sites interpolate it as "{age} ago" and a
   word there would read "never ago"; `AgeBadge` says **never** for a lane
   nothing has ever arrived on, because only the badge knows it was handed no
   timestamp at all. Say **which** absence, too: "never" and a timestamp we
   cannot parse are different things to tell an operator, so the badge's
   unparseable case reads **unknown** rather than borrowing the word.
   **The two age renderings that do not compose `AgeBadge` follow it**
   *(amended 2026-09-04, bead `ro-kukv.12`)*: the asset page's `LaneAge`, where
   no cadence is passed, says **never** / **unknown** in a section header, and
   the task page's `Age` says **"at an unknown time"** — one phrase, because
   neither of ITS absences is *never* (the comment was written, the task was
   created; the store simply recorded no time), with the title saying which.
   Both are labelled value slots — *created*, *updated*, an author, an event
   label, a section title — and none is the dense table cell this rule exempts.
7. **A qualifier that changes what a number MEANS ranks with the number.**
   Set it at least as prominently as the figures it governs — a chip in the
   heading, or the section's lead sentence. Only the *mechanics* (cadence,
   locale, storage) are small print. A caveat set smaller than everything it
   qualifies is a caveat nobody read *(2026-09-04, bead `ro-kukv.3`)*.
8. **The demo test (mechanical):** read every string on a screen aloud to
   someone who has never seen this repo. Any term you'd have to stop and
   define — and that isn't a justified exception above — fails review.
9. **A sweep is only true on the day it runs, so a test holds it**
   *(added 2026-09-04, bead `ro-ui73`)*. `scripts/ui-lexicon.test.mjs` reads
   the shipped strings of `apps/tower/{src,shared,worker}` — string and
   template literals and JSX text, never comments, identifiers or module paths
   — and fails on **bead, bd, spoke, hub, lane, pulse, asset #0, poller, knob**
   and the noun **register**. It is the sister of `ui-noun.test.mjs` (a site
   is never a *property*, D20) and it works the same way: exemptions are EXACT PHRASES with a
   reason, never widened patterns, and an exemption that stops matching is
   itself a failure. Three kinds of phrase qualify — a file path the operator
   executes against, a stored/wire/DOM value, and a search alias that is never
   rendered — plus one *mechanical* exemption, the command markup in the `bd`
   row above. **The Wall's held word was a fourth until 2026-09-05**; the
   operator ruled that the television says *Tasks* like every other screen
   (bead `ro-l1ed.7`), so that exemption is gone and nothing the product renders
   may say *bead* again. **Adding a word to that list is how
   this doc gets enforced; adding a phrase to the allowlist is how a decision
   gets recorded.** Neither is a way to make a failure go away.

   **The site noun is the one rule that decides by shape** *(added
   2026-09-23, D31, bead `ro-ujb9.142`)*. *asset* is the Tower's most common
   identifier, so a phrase allowlist would list every query key. The rule
   reads what the UX gate says a person reads (`extractVisibleStrings`) and
   treats as code only a path, a qualified or bound SQL name, and a string
   that is one lowercase token not handed to a label, title, placeholder or
   accessible name. Everything else that says *asset* fails, as does a
   singular/plural count of sites written anywhere but `site-noun.ts`. Its one
   phrase exemption is an owner chip naming the `assets` table.
