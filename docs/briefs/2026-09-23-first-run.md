# A fresh install reaches its first number (2026-09-23, bead `ro-ujb9.119`)

The flow gate walks every operator flow; until now none started on an empty
install and ended on a number. `first-data` stops when the connect panel reads
Working. The `fresh-install` walk in `apps/tower/e2e/ux-flows.mjs` goes one
step further — the panel's Open — and ends only when the site's Overview draws
its first collected number. Its first measurement is its budget, so the path
from nothing to a number can only get shorter.

Captures and the findings table: `docs/artifacts/first-run-2026-09-23/` (private historical evidence).

| Step | Screen | Role |

## Prior art

Researched 2026-09-23. Each product ends its setup on the product's own data,
not on a "setup complete" message.

- **Plausible Analytics — the first pageview.** After a site is added, its
  dashboard waits on one screen ("Waiting for first pageview") and becomes the
  dashboard the moment the first pageview lands; there is no separate
  confirmation step.
  https://plausible.io/docs/add-website ·
  https://github.com/plausible/analytics/discussions/728
- **PostHog — installation verified in the flow.** Onboarding watches for the
  first event from the snippet with a clear yes/no, then continues into the
  product with that event already visible.
  https://posthog.com/docs/getting-started/install ·
  https://www.command.ai/blog/unboxing-posthog/
- **Metabase — X-rays after the first connection.** Connecting a database is
  followed at once by automatically generated charts of the new data, so the
  first screen after setup already shows numbers.
  https://www.metabase.com/docs/latest/exploration-and-organization/x-rays
- **Grafana — data source, then a dashboard.** The getting-started path is
  "add a data source, then build a dashboard from it"; the first visualization
  is part of the same path.
  https://grafana.com/docs/grafana/latest/fundamentals/getting-started/first-dashboards/

**Adopted:**
- Plausible's and PostHog's end state: the flow is done when data is on the
  screen the operator will keep using, not when a connection reads green.
- Metabase's first screen after setup shows the new data's own numbers; the
  site's Overview must lead with the series that exists (the finding filed for
  the Overview's empty default chart).
- Grafana's two-step shape — source, then view — kept as one path with no
  detour: the connect panel's Open goes straight to the site.

## The clock

*Bead `ro-ujb9.134`.* The product ships UTC (`config/constants.json`
`os_time_zone`), and "yesterday's revenue", "today" and "this month" follow
that clock. While nobody has chosen one — no save ever set the zone, and the
saved zone is still the product's default (`timeZoneChosen` in
`packages/contract/src/time-zone-setting.ts`) — and the browser reads another
zone, the first-run card shows "Timezone UTC" and one button, "Use America /
New York". The press is the save, "Saved · Undo" sits beside it, and a page
view alone saves nothing. Settings → Time & timezone stays the place to
change it later. The flows the gate walks run in a UTC browser on a UTC
fixture, so they see no proposal and do not change.

### Prior art

Researched 2026-09-23.

- **Google Calendar — ask when the device's zone differs.** With "Ask to
  update my primary time zone to current location" on, Calendar asks before
  moving the calendar's zone; it never moves it silently.
  https://support.google.com/calendar/answer/37064
- **Cal.com — confirm the zone in the first onboarding step.** Onboarding
  asks for a name and to "confirm the Timezone that you're in", pre-filled
  from the browser.
  https://cal.com/help/quick-start/complete-onboarding
- **Slack — the device's zone, with a way back.** "Set time zone
  automatically" follows the device; unchecking it keeps a chosen zone.
  https://slack.com/help/articles/219889247-Manage-your-time-zone-preferences
- **Plausible — a site setting that sets the day boundary.** The report
  timezone lives in the site's General settings and decides where a day ends.
  https://plausible.io/docs/general

**Adopted:** Google Calendar's ask-never-assume and Cal.com's confirm-on-the-
first-screen, as one press with Undo; Plausible's rule that the zone is a
setting with its own home, which Settings keeps.
