# A new site is added in one screen (2026-09-23, bead `ro-ujb9.96.7.5`)

Adding an asset was a five-step wizard: 8 actions over 7 screens, three of
them defaults the operator clicked through, and a Review step repeating the
rail beside it (docs/reports/2026-09-23-ux-flow-audit.html, finding 5). It is
now one question asked over the page: the domain. Mockup frames e1-add,
e2-sources and e2-phone in
`integration-setup-mockup.html` (private historical evidence);
captures in
`ux-zero-2026-09-23/add-site/` (private historical evidence).

## What the operator sees

- **Add a site** — Home's first-run step 1, the Assets header and the sidebar
  open one card over the page they are on (the sidebar and old links through
  `/assets/new`, which is the Assets page with the card open).
- **Domain** — the one field. Paste anything: the scheme, `www.`, path and port
  come off.
- **The name** — read off the domain at once (`journey.example` → Journey
  Example), then replaced by the site's own name when its home page answers
  (`og:site_name`, else the brand part of its `<title>`); a caption says which.
  **The icon** is the site's favicon, or its initial where none answers.
  Neither ever holds Add up.
- **Not launched yet** — one optional press. A site that has not launched
  starts in the pre-launch stage, which the report-freshness check and the paid
  collectors skip: no alarm and no metered spend for a site with nothing to
  measure yet.
- **Refusals beside the field**: **Already added** at once, with Open to the
  one that is; **Not a domain** once Add is pressed. Add is never silently
  unavailable.
- **Add** lands on the new asset's **Data sources**: each source not connected
  shows **Connect** where its status would be, going straight to that
  provider's connect panel opened for this site
  (`/integrations?connect=<provider>&asset=<id>`).
- **Added, setup not saved** (the row landed, the config write did not) is its
  own state: what landed, what did not, **Retry setup** (re-sends only the
  acknowledged plan) and Open.

## What happened to each default the wizard asked

Every answer the wizard asked is still written — as the default it started
from — and each is changeable afterwards on the asset's own page:

| Wizard question | Written by the one-screen add | Changed later on |
|---|---|---|
| Display name | inferred from the site or the domain | Settings → Identity → Display name |
| Owning entity | nobody has said | Settings → Identity → Owning entity |
| Manual lifecycle stage | Onboarding, or Pre-launch with the one press | Settings → Manual lifecycle stage |
| Monitor only | Monitor only | Settings → Automation |
| Data collection (push / pull) | the asset sends its own report (push) | Settings → Data collection → **Fetch from an endpoint** *(new)* |
| Totals on the card | none | Settings → **Card totals** *(new)* |
| Each source: Not set up / Skip + reason | Not set up | Data sources → the source's row (Not using) |

## How it is built

- **The same write path.** `siteDraft` is the wizard's `emptyDraft` with the
  domain, the name and the stage; `planWrites` composes the same store row and
  the same one changeset; `lib/asset-operations.ts` writes the row first and
  the changeset second, unchanged. Pinned by
  `apps/tower/test/asset-wizard.test.ts` ("writes for a one-screen site exactly
  what the wizard wrote from its defaults") and
  `apps/tower/test/add-site.test.tsx`. No new write path, no migration.
- **The Settings additions reuse the add's own ops**: `pullEntryOp` and
  `countersEntryOp` (apps/tower/shared/asset-wizard.ts) are what `planWrites`
  sends and what `routes/asset-detail/CollectionSetup.tsx` sends
  (`apps/tower/test/collection-setup.test.tsx`).
- **The site's name** comes from `GET /api/site-name`
  (apps/tower/worker/site-name-route.ts): only `https://<domain>/`, only a
  public-looking DNS name (no IP literal, `localhost` or internal top level,
  checked again on every redirect it follows by hand), 3 seconds, 64 KB, no
  credentials, and every failure answers `{ name: null }`. The parsing is pure
  (apps/tower/shared/site-name.ts, `apps/tower/test/site-name.test.ts`).

## Prior art

Researched 2026-09-23 from each vendor's own documentation.

- **Plausible Analytics — add a website.** Sites → Add a website → the domain
  (docs say to leave off `https://` and `www.`) → Continue → the install page.
  The domain is the only input.
  https://plausible.io/docs/add-website ·
  https://plausible.io/docs/landing-page
- **Fathom Analytics — add a site.** Settings → Sites → Add site → one name
  field, "for internal purposes only" → the embed code. One field, and the site
  id is generated.
  https://usefathom.com/docs/account/add-delete
- **Simple Analytics — add a website (Admin API).** Only `hostname` is
  required; `timezone` defaults to UTC when omitted, `label` and `public` are
  optional.
  https://docs.simpleanalytics.com/api/admin
- **Vercel — add a domain / import a project.** Framework and build settings
  are detected and filled in on import; adding an apex domain proposes the
  `www` variant and suggests the DNS record type from the domain's shape.
  https://vercel.com/docs/domains/working-with-domains/add-a-domain
- **Cloudflare — onboard a domain.** One field (the apex domain), validated
  against the Public Suffix List before anything is created; existing DNS
  records are detected by a quick scan and reviewed rather than typed.
  https://developers.cloudflare.com/fundamentals/manage-domains/add-site/
- **Google Search Console — add a property.** Domain property (the bare
  domain, all subdomains and protocols) or URL-prefix; verification can come
  later, and data collection starts when the property is added.
  https://support.google.com/webmasters/answer/34592 ·
  https://support.google.com/webmasters/answer/10431861
- **Ahrefs — add a project.** Enter the domain; the project name is filled in
  from the page's HTML `<title>` and stays editable.
  https://help.ahrefs.com/en/articles/1433362-how-to-add-a-project-in-your-dashboard

**Adopted:**
- Plausible's, Cloudflare's and Simple Analytics' one required input: the
  domain, forgiving about what is pasted.
- Ahrefs' name from the site's own page, editable afterwards; Vercel's
  detect-and-default for everything else, changeable on Settings.
- Cloudflare's validation before anything is created, beside the field.
- Plausible's and Search Console's landing on the new site at once, with its
  next actions (here: one Connect per source).
- None of the seven asks a "kind" of site at add time. The one optional press
  kept here, **Not launched yet**, is not a category: it is the one default
  whose wrong answer costs money and raises a false alarm on day one.
