# `integrations.json` — the per-asset integration scope/setup register

Per asset × per data source: whether that lane applies and what setup is
known. Current health for automated lanes is observed from collector runs; it
is not a switch in this file. This is the living form of the "inventory
pending" that [decisions.md](decisions.md) D5 (revenue plumbing) and D8
(analytics inventory) point at.

**Seed and export, not source of truth** (D22): `pnpm config:seed` loads this
installation's copy (else this generic default) into the store's
`config_documents` table, the running OS reads and saves it there, and
`pnpm config:export` writes it to `installation/`. Until an install seeds,
every read falls back to the copy compiled into the Workers. The register
changes in the store — from a site's Sources tab or with `pnpm config:apply`,
never from a cron or a health control. The catalog half ships with the product.

### What the Tower may edit here

Generated by `pnpm config:docs -- --write` from `scripts/config-registers.mts`, the one declaration of every register and knob; `scripts/config-docs.test.mjs` fails when this block is stale.

**Site data sources** (`asset-integrations`) — one site's data sources. Rows live at `/assets` of `config/integrations.json` (object, keyed by asset-id); edited from Add a site (/assets/new). Rows are added and removed whole; no field inside one is set through the register.

**Site data sources** (`asset-lane`) — one data source on one site. Rows live at `/assets/{asset}` of `config/integrations.json` (object, keyed by lane-id); edited from the site's Sources tab.

| Field | Label | Type | Required | Hint | Rule |
|---|---|---|---|---|---|
| `status` | Posture | `enum` | yes | set up, or skipped with a reason | one of `live`, `degraded`, `needs-setup`, `skipped`, `not-applicable` |
| `note` | Reason | `string` | no | one line: why skipped, or what blocks it | up to 90 characters |
| `ref` | Source pointer | `string` | no | which credential reaches this site — a convention or placeholder, never a secret | up to 200 characters |
| `since` | Since | `date` | yes | when this posture was recorded, YYYY-MM-DD | — |
| `mediavineSiteId` | Mediavine site | `string` | no | copy the site id from Mediavine | up to 160 characters; matches `^[A-Za-z0-9+/=_-]+$` |
| `mediavineEnabled` | Automatic Mediavine sync | `boolean` | no | collect yesterday at 6:10 a.m. Pacific; disabling preserves saved revenue | — |
| `revenueHolidayCalendar` | Revenue forecast holiday calendar | `enum` | no | holidays compared with this site’s traffic | one of `none`, `US`, `CA`, `US,CA` |
| `propertyId` | GA4 property id | `string` | no | digits only, e.g. 313598867 | up to 20 characters; matches `^[1-9][0-9]{4,14}$` |
| `siteUrl` | Site | `string` | no | use sc-domain:example.com or https://example.com/ | up to 253 characters; matches `^(?:sc-domain:[a-z0-9][a-z0-9.-]*\.[a-z]{2,}|https?://\S+)$` |
| `locationCode` | Location | `integer` | no | DataForSEO's numeric location code — 2840 is the United States, the portfolio baseline | 1 to 99999999 |
| `languageCode` | Language | `enum` | no | DataForSEO's language code — 'en' is the portfolio baseline | one of `en`, `es`, `fr`, `de`, `pt`, `it`, `nl`, `pl` |
| `host` | PostHog region | `enum` | no | us or eu | one of `us`, `eu` |
| `projectId` | PostHog project id | `string` | no | the number in the project's URL (us.posthog.com/project/596607), digits only | up to 12 characters; matches `^[1-9][0-9]{0,11}$` |
| `funnels` | Funnels | `posthog-funnels` | no | 2 to 10 steps each, in order | — |

**Data-source catalog** (`data-source-catalog`) — one data source the product can collect. Rows live at `/catalog` of `config/integrations.json` (array, keyed by `id`); edited from none — it ships with NoticeOS and changes with a product update.

| Field | Label | Type | Required | Hint | Rule |
|---|---|---|---|---|---|
| `id` | Id | `string` | yes | lowercase-with-dashes: bing-webmaster | up to 40 characters; matches `^[a-z0-9]+(?:-[a-z0-9]+)*$`; fixed once written |
| `label` | Label | `string` | yes | what the product calls it | up to 80 characters; fixed once written |
| `scope` | Scope | `enum` | yes | whether it collects for a site, for the OS, or both | one of `property`, `portfolio`, `both`; fixed once written |
| `layer` | Layer | `enum` | yes | whose failure a red cell reports | one of `os`, `provider`, `property`; fixed once written |
| `credential` | Credential | `enum` | yes | whether one credential can serve more than one site | one of `shared`, `per-property`; fixed once written |
| `docRef` | Doc | `string` | yes | the doc section that explains it | up to 200 characters; fixed once written |

## The honesty definition of "live"

> **`live` means THE OS CAN CONSUME THE LANE end to end — not that the asset has
> the tag / link / App installed.**

A GA4 tag firing on the site, an unarchived provider script, or a live CJ
program are **not** `live` here if the OS's central pull/cron/ingest that would
consume them isn't built. Each lane's exact bar is its row in
[doc 11's catalog](../docs/11-integrations.md#the-catalog) (GA4 `live` = "the
central GA4 pull returns this asset's sessions/events on the Sense cron," not
"the tag fires"). An agent that plans from a lane it can't actually read is
confabulating ([doc 11](../docs/11-integrations.md)).

## The five states (verbatim from doc 11)

`live | degraded | needs-setup | skipped | not-applicable`

- **`live`** — the OS can consume the lane now. For collector-backed lanes
  this renders only from a fresh successful run.
- **`degraded`** — a reduced-capability lane; for collector-backed lanes,
  rendered from the latest error or stale run.
- **`needs-setup`** — relevant but not yet consumable (creds, cron or wiring
  missing, or blocked upstream on a provider approval).
- **`skipped`** — relevant but operator-declined for now; **reason required**
  in the `note`. You can only decline something that was on the table.
- **`not-applicable`** — the catalog says this lane never applies to this
  asset: asset #0 (the OS itself) has no organic-search or revenue surface.

## Health is observed, not edited

For GA4, GSC and Bing Webmaster the Tower loads the latest `signal_runs`
attempt; for DataForSEO, the newest attempt for each required
`signal_dump_runs` report family. On every read a fresh success is `live`, a
latest error or a run older than the lane's cadence allows is `degraded`, and
no attempt on record is `needs-setup` — whatever older value the file holds.
`skipped` and `not-applicable` stay file-owned: evidence never enrolls a
deliberately excluded asset. Lanes without an automated health source use the
file-backed status until a collector lands.

The Tower therefore has no health editor and never will: the Sources tab edits
the scope decision and the mapping, and the chip beside them keeps reporting
what the collectors observed.

## Invariants beyond the field rules

- Every `assets.<id>` key is an id in `noticeos.assets` — the same set, no
  more, no fewer, asset #0 included; [`signal-panels.json`](signal-panels.README.md)
  holds its roster to the same set.
- Every asset carries an entry for every catalog lane **that the `scope` rule
  does not already answer**. `undeclaredLanes` in
  `apps/tower/shared/integrations.ts` derives the missing cells and
  `apps/tower/test/integrations-payload.test.ts` holds the committed file to
  declaring them all.
- Every `skipped` entry states a reason in its `note`. A `note` is absent
  until there is something to say, never blank, and it is a reason, never a
  log: proof is the collectors' stored runs, and saved changes are recorded in
  `config_changes`.
- `ref` is a placeholder or convention (`sc-domain:<domain>`), never a real
  id or secret. Credentials are connected on **Integrations** and stored
  encrypted; [Operations](../docs/06-operations.md#bootstrap-secrets-vs-integration-credentials)
  distinguishes them from bootstrap secrets. This register records status and
  refs, never credentials.
- `since` is the day the standing posture was taken: saving a new `status`
  re-dates the cell (a `stamps` pair on the register); a reason-only edit
  leaves it alone.

## Scope — the register stores obligations, not the whole grid

| `scope` | Means | Derived cells |
|---|---|---|
| `property` | a content asset's own surface — organic search, analytics, an ad network | `not-applicable` on asset #0 |
| `portfolio` | the OS's own lane, run once for everything (operator notifications) | `not-applicable` on every content asset |
| `both` | applies either side (`uptime`, `github-app`) | none — every cell is declared |

A cell the rule answers is not written down; the Tower generates it, state and
sentence, at render time (`registerCell` in `apps/tower/shared/integrations.ts`).
The rule wins over a declared cell, and a payload test asserts the file carries
none it would derive. A new asset arrives owing decisions rather than
paragraphs.

## Layers — whose failure a lane reports

Health groups rows by `layer`, in this order, because a red row in one layer
explains the red rows under it:

| `layer` | Means | Example |
|---|---|---|
| `os` | this machine and its own connection to the internet | the derived `egress` lane — no cell in this file |
| `provider` | a third-party service, and the account the OS reads it with | `gsc`, `clarity`, `dataforseo`, `github-app` |
| `property` | the asset's own plumbing has to reach the OS; no third party involved | `deploy-annotations`, the derived `nightly-report` lane |

The layer exists because an operator's home internet once went down and every
nightly lane, running from that machine, flagged six assets as dark. The OS now
decides fault before it attributes a failed fetch
(`workers/ingest/src/egress.ts`, `noticeos.egress_checks`): if the `os` row is
red, nothing below it was measured. `layer` is not `credential` restated —
`clarity` and `posthog` are provider lanes that issue one token per project —
so both are declared.

## Credential scope

- **`shared`** — one credential may serve several assets (Google signal
  service accounts, the DataForSEO login, the GitHub App). The per-asset cell
  then tracks **enrollment**, not a duplicated secret: what each asset still
  needs (a GA4 Viewer or GSC grant, an App installation) is the Sources tab's
  provider-side step.
- **`per-property`** — no portfolio credential exists (Clarity issues tokens
  per project, PostHog one key per project, deploy-annotations is wiring in
  each asset's own pipeline). Every cell is its own setup task.

## The catalog: what is in it, and who edits it (nobody in the Tower)

The register tracks only per-asset lanes — the doc-11 rows whose setup and
health differ per asset; portfolio-level rows (model providers, Ahrefs, web
search, feeds, Cloudflare infra) are owned once at the OS level.
`discord-webhooks`, `uptime` and `github-app` are included because they are
asset #0's own integrations. `affiliate-cj` and `affiliate-amazon` are
separate lanes because two networks run simultaneously with different
postures; ad networks are one lane, `ad-network`, because AdSense →
Raptive/Mediavine is a sequential migration. Mediavine's `mediavineSiteId` and
`mediavineEnabled` sit on that cell, with credentials in Connected accounts
([Mediavine revenue](../docs/11-integrations.md#mediavine-revenue)).

The catalog is the product's own definition of the sources it can collect,
not a setting: every field is fixed once written, so the write lane refuses an
edit from any door. `id` is the join key every site entry and every collector
names the source by — a row with no collector behind its id never collects.
The register stays declared so a product update can insert or retire a
catalog row by changeset. What an operator sets about a source lives where it
is used: the credential on **Integrations**, a site's mapping and "Not using"
on its **Sources tab**, when each collection runs on **Settings → Data
collection**.

**A row nothing connects yet is not offered.** The affiliate rows,
`deploy-annotations` and `github-app` have no provider card (`laneProvider`
finds none); while such a cell is only `needs-setup`, no screen draws a row
for it unless something already arrived for it. **`uptime` needs no
connection**: the OS checks each site's home page itself every hour, and the
cell reads that check unless the file says `skipped` or `not-applicable`.

## A site's own lanes: the Sources tab

The `assets` half is the `asset-lane` register, edited on the asset's own
Sources tab, one section per lane card. It carries the posture (only
`needs-setup` and `skipped` are offered; the rest are derived), the setup
steps (derived on every read, never tickable), and the mapping fields,
validated against the declaration before they are sent and again when they
land. PostHog's `funnels` is one structured value, judged by
`posthogFunnelsRefusal` in `packages/contract/src/configuration.mts` — the
function the collector checks before it builds a query.

**How a decline is recorded.** "Not using" opens three reasons in place —
*Don't use this product*, *Replaced by another tool*, *Not relevant for this
site* — or a line of the operator's own. The press is the save: reason and
`status: skipped` land in one changeset with Undo; "Use again" is one press
back to `needs-setup`. Nothing is preselected. The product writes the
`REASON:` prefix (`declineNote` in `apps/tower/shared/lane-decline.ts`),
which satisfies the `/reason/i` check below and tells a decline apart from a
note saying what blocks a source in use. Mediavine's settings save never
declines: switching a running sync off is the Ad revenue row's Not using
(`workers/ingest/test/mediavine.test.ts`).

**What the collectors do with a decline.** A `skipped` or `not-applicable`
cell is not collected at all — no request, no attempt row, no spend. One rule,
`laneDeclined` / `cellDeclined` in `workers/ingest/src/lane-mapping.ts`, is
asked by every collector before a target is built;
`workers/ingest/test/not-using.test.ts` proves a declined site is neither
requested nor billed.

**What the collectors read is this file.** `workers/ingest/src/lane-mapping.ts`
answers every lane's "which property is this asset" from the mapping fields
first. Where an asset states nothing, GA4 and Search Console fall back to the
`GOOGLE_SIGNAL_ACCOUNTS` credential's own property map, Bing to matching the
asset's domain against the central account's verified sites, DataForSEO to the
US/English baseline (2840, `en`). Each run records which answered
(`mappingSources` on its completion line). The Google fallback is read only
while at least one asset the blob names is unmapped here, and the Google card
on `/integrations` says which state holds.

**Timing.** Once seeded, the ingest resolves this document store-first on
every cron fire (`workers/ingest/src/config-store.ts`), so a value saved on
the Sources tab is what the next run asks for — no restart, no deploy. Before
seeding, both Workers read the compiled copy and a hand-edited file waits for
a restart; the Sources tab derives which sentence it prints from
`GET /api/config`'s `sources` entry (`laneMappingTiming`).

## Validation

The missing-entry invariant is a gate
(`apps/tower/test/integrations-payload.test.ts`). To check the rest by hand,
replace `example.com` with the OS site id (a fresh checkout has no sites, so
it may be left out):

```bash
node --input-type=module -e '
// The register this installation uses: its own export when it has one
// (`pnpm config:export` writes installation/, or NOTICEOS_INSTALLATION_DIR),
// otherwise the product default here in config/.
import fs from "node:fs";
import { readablePath } from "./scripts/installation.mjs";
const file=readablePath("integrations.json");
const j=JSON.parse(fs.readFileSync(file,"utf8"));
// The OS site (the `assets` row with is_os = 1), the one argument once the
// register holds sites. Which sites exist is for the store to say, not this
// file or the migrations: sites are added in the Tower.
const OS=process.argv[1];
if(Object.keys(j.assets).length&&!OS) throw new Error("pass the OS site id");
const SCOPE=Object.fromEntries(j.catalog.map(c=>[c.id,c.scope||"property"]));
const catIds=j.catalog.map(c=>c.id);
const STATES=["live","degraded","needs-setup","skipped","not-applicable"];
const LAYERS=["os","provider","property"];
const errs=[];
// Declared, never defaulted: a lane in a layer by omission still claims one.
for(const c of j.catalog) if(!LAYERS.includes(c.layer)) errs.push(`catalog ${c.id} bad/missing layer`);
for(const[a,lanes]of Object.entries(j.assets)){
  const isOs=a===OS;
  for(const c of catIds){
    // A cell the scope rule answers must be ABSENT; any other lane must be present.
    const ruled=(SCOPE[c]==="property"&&isOs)||(SCOPE[c]==="portfolio"&&!isOs);
    if(ruled&&(c in lanes)) errs.push(`${a}.${c} is derived — delete it`);
    if(!ruled&&!(c in lanes)) errs.push(`${a} missing ${c}`);
  }
  for(const[l,e]of Object.entries(lanes)){
    if(!STATES.includes(e.status)) errs.push(`${a}.${l} bad status`);
    if(e.status==="skipped"&&!/reason/i.test(e.note)) errs.push(`${a}.${l} skipped w/o reason`);
    if(!/^\d{4}-\d{2}-\d{2}$/.test(e.since||"")) errs.push(`${a}.${l} bad since`);
  }
}
console.log(errs.length?errs:"OK", file);
' example.com
```

The command prints `OK` and the resolved path: the generic default on a fresh
checkout, or the installation's export when present.
