# `pull.json` — the assets whose nightly pulse the OS fetches

NoticeOS runs local-first: an asset that cannot reach the OS to *push* its
nightly pulse is instead **pulled**. A nightly cron fetches each enabled row's
own self-report endpoint, turns the response into a contract envelope, and
writes it through the same path as an inbound `POST /api/pulse`, so a pulled
asset is held to the identical contract as a pushed one
(`workers/ingest/src/pull.ts`). When an asset later starts pushing, its row is
set to `enabled: false` and the two lanes never collide.

**Seed and export, not source of truth**: `pnpm config:seed` loads this
installation's copy (else this generic default) into the store, the running OS
reads and saves it there, and `pnpm config:export` writes it to
`installation/`. Until an install seeds, every read falls back to the copy
compiled into the Workers. A fresh clone pulls nobody: the file is `[]`.

**Asset metrics endpoints** (`asset-pull`) — one asset's own metrics endpoint. Rows live at `/` of `config/pull.json` (array, keyed by `asset`); edited from Add an asset, then the asset's Settings tab (Fetch from an endpoint). Rows are added and removed whole; no field inside one is set through the register.

## Semantics worth knowing

- A row holds the asset's `asset`, its endpoint `url`, `enabled`, and a
  `format` that selects the wire shape: `prometheus` (a text scrape the
  adapter parses, with a `metrics` map from envelope metric name to the
  Prometheus `table` label, computing `avg7d` from stored pulse history) or
  `envelope` (the endpoint already returns the contract envelope verbatim; the
  adapter validates it, guards that its `asset` matches the configured id, and
  hands it on — the source's own `avg7d` is authoritative).
- Auth is the asset's static bearer token, read from the ingest Worker's one
  `ASSET_TOKENS` map — the same entry the push lane checks inbound pulses
  against, because an asset holds exactly one secret gating both directions. A
  pulled endpoint is therefore one gated on that token, never a session-gated
  admin page.
- A row may include `additionalEndpoints`, each with `url`, `format: "envelope"`
  and `enabled`. These endpoints use the same asset token. The adapter validates
  each envelope's asset and reporting day, rejects duplicate metrics, and stores
  the combined metrics and session reports in one daily revision. A failed
  supplemental request retains the primary metrics and keeps the pull alert open.
  Keep a new endpoint disabled until its first live read is approved.
- The metric map is structural config, view-only in the Tower; an asset's whole
  row is added from the add-asset flow and its Settings tab.
