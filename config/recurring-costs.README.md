# `recurring-costs.json` — the subscriptions the ledger cannot discover

Fixed monthly subscriptions the operator declares from invoices or statements.
Each entry books every month from its start month through its end month,
alongside the ledger's other recorded costs.

**Seed and export, not source of truth** (D22): `pnpm config:seed` loads this
installation's copy (else this generic default) into the store's
`config_documents` table, the running OS reads and saves it there, and
`pnpm config:export` writes it to `installation/`. Until an install seeds,
every read falls back to the copy compiled into the Workers.

### What the Tower may edit here

Generated by `pnpm config:docs -- --write` from `scripts/config-registers.mts`, the one declaration of every register and knob; `scripts/config-docs.test.mjs` fails when this block is stale.

**Recurring costs** (`recurring-costs`) — one unmetered subscription, booked every month it runs. Rows live at `/costs` of `config/recurring-costs.json` (array, keyed by `id`); edited from /financials.

| Field | Label | Type | Required | Hint | Rule |
|---|---|---|---|---|---|
| `id` | Id | `string` | yes | lowercase-with-dashes: claude-code | up to 64 characters; matches `^[a-z0-9]+(?:-[a-z0-9]+)*$`; fixed once written |
| `label` | Label | `string` | yes | what the charge is called on the statement | up to 80 characters |
| `asset` | Site | `asset-id` | yes | who carries it — the OS for anything portfolio-wide | — |
| `family` | Family | `enum` | yes | the ledger group it books under | one of `inference`, `api`, `infra`, `operator`, `os-overhead` |
| `amountUsdPerMonth` | USD / month | `number` | yes | the recurring charge | at least 0; fixed once written |
| `from` | From | `month` | yes | first month to book, YYYY-MM | — |
| `to` | To | `month` | no | last month to book, YYYY-MM | — |
| `note` | Note | `string` | no | copied onto each month's cost | up to 400 characters |

## Assign each cost to the asset it supports

Assign a subscription used by one site to that site's asset, and tools and
hosting shared across the portfolio to **the OS's own asset**, asset #0 —
[doc 00](../docs/00-objective-and-roi.md) calls this "the system bills
itself". The ledger keeps direct site costs separate from shared operating
costs, without distributing overhead by an unsupported allocation:

```
asset net       = its revenue − its DIRECT cost
portfolio net   = Σ site asset nets − asset #0 overhead
```

## Semantics worth knowing

- **`id` becomes part of the ledger's idempotency key**, so renaming it
  re-books every month.
- **`amountUsdPerMonth` is fixed once added** because every booked month was
  booked at it. A price change closes the old entry with `to` and adds a new
  one with a new `id`, the way Stripe keeps a price's amount and has you add a
  new price; the row's **To** and the table's **Add** are both on the table.
  Do not edit a past month's figure and re-run: the route refuses it as
  `conflicting_replay`, correctly, because a booked month is history.
- **`family`** is a `cost` family from the `ledger` CHECK. **`to`** is
  omitted while the subscription is live. **`note`** rides onto the ledger
  row.

## Booking

```sh
node scripts/cost-import.mjs --through 2026-08     # recurring + metered data spend
node scripts/cost-import.mjs --through 2026-08 --dry-run
```

Idempotent: replaying books nothing. Everything lands `estimated` — a
subscription is a standing charge, not a reconciled invoice, and calling it
reconciled would erase the figure a real statement is measured against.

## Where it is edited

**`/financials` → *Declared costs***, on the page whose *Stated* figures these
rows produce: add, change and remove go through the same validated write lane
a settings knob uses — one changeset per action, Undo in the toast, the month
totals recomputed after the save. A row the declaration refuses is refused in
the browser, beside the field. Outside the Tower, `pnpm config:apply` makes
the same store write; the file in the installation folder is its export.

## Include renewal orders

Recurring subscriptions do not supply domain renewal charges. Record those in
[domain costs](domain-costs.README.md) from the amounts actually paid; a
missing order leaves that site's direct cost and margin incomplete.
