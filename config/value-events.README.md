# config/value-events.json — the events an asset calls value, per asset

Which GA4 events each asset considers a **value event**: the things that, if
they happen, mean the product did part of its job. The
`value-event-not-key-event` rule in
[`scripts/signal-insights.mjs`](../scripts/signal-insights.mjs) compares this
declaration against what GA4 actually counts as a **key event** and warns when
the two disagree. The document records an intent that no provider can infer;
the observations stay in the immutable archive.

**Seed and export, not source of truth**: `pnpm config:seed` loads this
installation's copy (else this generic default) into the store, the running OS
reads and saves it there, and `pnpm config:export` writes it to
`installation/`. Report analysis requires a valid saved document — an
unseeded, unavailable or malformed configuration stops analysis before output
files are replaced, and the export is never substituted. The analyzer records
the document version it read as `summary.json` →
`configuration.valueEventsVersion`.

### What the Tower may edit here

Generated by `pnpm config:docs -- --write` from `scripts/config-registers.mts`, the one declaration of every register and knob; `scripts/config-docs.test.mjs` fails when this block is stale.

**Sites declaring value events** (`value-events-assets`) — one site's value-event declaration, holding its list. Rows live at `/assets` of `config/value-events.json` (object, keyed by asset-id); edited from the site's Sources tab. Rows are added and removed whole; no field inside one is set through the register.

**Value events** (`value-events`) — one GA4 event this site calls a value event. Rows live at `/assets/{asset}/valueEvents` of `config/value-events.json` (array, keyed by `event`); edited from the site's Sources tab.

| Field | Label | Type | Required | Hint | Rule |
|---|---|---|---|---|---|
| `event` | GA4 event | `string` | yes | verbatim as the site emits it (calculation_complete, never "Calculation complete") | up to 40 characters; matches `^[A-Za-z][A-Za-z0-9_]*$` |

**Product use stages** (`product-use-stages`) — saved event counts shown in Product use. Rows live at `/assets/{asset}/productUseStages` of `config/value-events.json` (array, keyed by `eventName`); edited from the site's Sources tab.

| Field | Label | Type | Required | Hint | Rule |
|---|---|---|---|---|---|
| `eventName` | GA4 event | `string` | yes | the saved event name | up to 40 characters; matches `^[A-Za-z][A-Za-z0-9_]*$` |
| `label` | Label | `string` | yes | the stage heading | up to 60 characters |
| `group` | Group | `enum` | yes | the display group | one of `primary`, `sharing`, `supporting` |
| `compareTo` | Compare to event | `string` | no | another declared event volume | up to 40 characters; matches `^[A-Za-z][A-Za-z0-9_]*$` |
| `comparisonLabel` | Comparison label | `string` | no | the independent-volume comparison heading | up to 60 characters |

## Why it exists

One site's core value event carried `keyEvents = 0` for months while a minor
event carried 142, and nothing in the OS noticed. A value event that is not a
key event does not read as a small conversion number: it reads as **zero**, in
every conversion-flavored card, forever — a misconfiguration presented as user
behavior.

## Semantics worth knowing

- **Event names are verbatim** as the asset emits them. Order is not
  meaningful; duplicates collapse.
- **An asset with no entry is silent** — the rule emits nothing. Absence is
  *not declared*, never *nothing to declare*.
- **A declared event GA4 reported no row for is unknown, not zero**: it could
  be a renamed tag or a quiet week. Only events GA4 reported, above a volume
  floor, can fire.
- **Declared ≠ instrumented.** Listing an event does not make it fire; an
  event absent from GA4 entirely is a collection question for the
  `measurement-integrity` rule.
- **The rule only reads.** This file is the declaration, and the GA4
  key-event setting is inside the measurement channel — `forbidden` class per
  [AGENTS.md](../AGENTS.md). The OS can say the two disagree; it cannot say
  which is wrong, and it must never edit either.
- **Key events are a GA4 property setting** and a change applies going
  forward only: GA4 does not backfill, so a window spanning a change shows
  both states and the series steps. A step is not an anomaly, and the zeros
  before it are not evidence about conversion.

## Product use stages

`productUseStages` selects already saved event-user counts for Product use on
the Growth tab. It collects nothing, registers no conversion and changes no
rule. Rows keep their order within each group; the display reads primary,
sharing, then supporting; the portable
[stage contract](../packages/contract/src/product-use.mts) validates stored
settings and readers (at most 32 stages, unique event names).

`compareTo` names another declared event whose independent user count is the
denominator; a missing count or zero denominator withholds the comparison, and
`comparisonLabel` supplies its heading. These are independent event-user
volumes, not a same-person conversion or funnel. Daily unique users are never
added together: the section uses one retained 28-day GA4 aggregate and shows
its exact dates.

The GA4 card on Sources edits this list through the collection editor. A first
stage creates only its list, or a stages-only asset holder when none exists;
saved-version guards prevent replacing a concurrent value-event declaration,
and Undo removes only the stages list.

## Where it is edited

**The asset's Sources tab** (`/assets/<id>/sources`), inside the GA4 lane's
own card. Add, rename and remove are one changeset each with Undo, and a name
is refused against the register's rule before anything is sent. An asset with
no entry shows an empty list with **Add**, and that first row files the
asset's entry — a pointer never creates structure. `pnpm config:apply` uses
the same saved document; editing an exported file alone changes nothing.

**The asset page's Delete removes the whole entry**: an asset's own GA4
declarations are part of what the asset is.

**The add-asset wizard deliberately does not ask.** A declaration is tuned
against what GA4 actually counts, a comparison nobody can make on the day an
asset is created.

## Seeds

A fresh clone declares no value events and no stages.
