# config/ga4-custom-dimensions.json — where the operator registered GA4 event parameters

**This file declares a fact about GA4 admin, not a preference.** GA4 answers a
Data API query for an event parameter only after an operator has registered
that parameter as a **custom dimension** in the GA4 property (Admin → Custom
definitions). This file is the OS's record of where that has been done, so
families that read event parameters ask only the assets that can answer.

It changes nothing in GA4. Registering is operator work — the analytics
pipeline is `forbidden`-class ([AGENTS.md](../AGENTS.md)), so this repo reads
the measurement channel and never configures it. Adding an asset here asserts
that the operator already made its dimensions exist.

**Seed and export, not source of truth**: `pnpm config:seed` loads this
installation's copy (else this generic default) into the store's
`config_documents` table, the running OS reads and saves it there, and
`pnpm config:export` writes it to `installation/`. Until an install seeds,
every read falls back to the copy compiled into the Workers.

### What the Tower may edit here

Generated by `pnpm config:docs -- --write` from `scripts/config-registers.mts`, the one declaration of every register and knob; `scripts/config-docs.test.mjs` fails when this block is stale.

**Sites with registered dimensions** (`ga4-event-params-assets`) — one site's registered-dimension declaration, holding its list. Rows live at `/assets` of `config/ga4-custom-dimensions.json` (object, keyed by asset-id); edited from the site's Sources tab. Rows are added and removed whole; no field inside one is set through the register.

**Registered event parameters** (`ga4-event-params`) — a parameter registered as a GA4 custom dimension. Rows live at `/assets/{asset}/eventParams` of `config/ga4-custom-dimensions.json` (array, keyed by `param`); edited from the site's Sources tab.

| Field | Label | Type | Required | Hint | Rule |
|---|---|---|---|---|---|
| `param` | Parameter | `string` | yes | as the site sends it, e.g. message | up to 40 characters; matches `^[A-Za-z][A-Za-z0-9_]*$` |

## Semantics worth knowing

- **A parameter is written as GA4 names it in the emitter** (`message`), not
  as the Data API addresses it (`customEvent:message`); the collector adds the
  prefix.
- **An asset with no entry is skipped silently** — no request, no manifest
  row, no error. A daily error row for an asset the operator has deliberately
  not set up would be an alarm about a settled decision.
- **A family is offered to an asset only when every parameter it needs is
  listed.** The `js-errors` GA4 daily archive needs `message` and `source`
  (`workers/ingest/src/signal-dumps.ts`); a partially registered asset is
  skipped rather than asked for a field that would fail.

## Why the unregistered state still exists

Skipping the unlisted assets does **not** retire
`ga4_custom_dimension_unregistered`. **Registration is forward-only**: GA4
backfills nothing, so an asset listed here can still be asked for a date
before its registration and be rejected or answered with `(not set)` — a
per-date unknown, never an error-free day. And **this file can be wrong**: it
is a hand-maintained claim about a system it cannot inspect, so if someone
lists an asset whose dimensions were never created, the collector says so
distinctly rather than recording an empty success.

## Where it is edited

**The asset's Sources tab** (`/assets/<id>/sources`), inside the GA4 lane's
card, beside the value-event declaration. Add, rename and remove are one
changeset each with Undo, and a name is refused against the register's rule
before anything is sent. An asset with no entry shows an empty list with
**Add**, and that first row files the asset's entry. `pnpm config:apply`
makes the same validated store write; the file in the installation folder is
its export.

**The asset page's Delete removes the whole entry**: an asset's own GA4
declarations are part of what the asset is.

**The add-asset wizard deliberately does not ask.** Registration happens in
GA4 admin on a property that already exists, and this file records it
afterwards; a field at creation time would collect an intention rather than
the fact this file is for.

## Seeds

A fresh clone registers no site: an asset is listed here only after its
dimensions exist in its GA4 property.
